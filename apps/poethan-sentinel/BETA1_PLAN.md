# Poethan Sentinel Beta 1 后续计划

版本目标：`0.1.0-beta.1`

## 当前实现状态（2026-08-29）

WebApp 的工程、服务器配置、插件动态表单、签名验证、远端版本缓存、`/tmp` 结果下载、SSE、报告、AI、演示模式、安装脚本和自动化测试均已落地。三个官方插件已使用 Beta 开发公钥签名，篡改测试和完整演示工作流测试通过。

正式对外发包前只保留三项需要仓库所有者或真实环境参与的发布门槛：

1. 选择项目开源许可证。
2. 在离线安全位置生成正式发布私钥，替换 Beta 开发公钥并重新签名。
3. 在干净 macOS 用户和至少一台真实 Linux 服务器完成一次人工回归。

构建发布包执行 `poethan-sentinel-webapp/scripts/package-release.sh`，会先运行全套检查并生成 SHA-256。

Beta 1 的目标不是继续扩展检查项，而是把当前 HTML 原型变成一套可以公开安装、完成一次真实诊断、并且对插件来源有明确安全保证的本地优先工具。

## 1. Beta 1 用户闭环

公开版本必须完整支持以下流程：

```text
启动本地 WebApp
    ↓
新建并测试服务器
    ↓
安装或扫描受信插件
    ↓
单选一个插件并填写配置
    ↓
通过 SSH 执行诊断
    ↓
查看原始输出和确定性结论
    ↓
可选 AI 分析
    ↓
保存、复制或导出报告
```

以下情况不能依赖控制台排查，必须在页面上给出原因和处理入口：

- SSH 登录失败。
- 插件格式错误或签名不可信。
- 服务器缺少 Python、Bash、perf 等运行依赖。
- 插件上传或远程安装失败。
- 诊断脚本超时、被停止或退出码非零。
- 结果包下载、Schema 校验或模板渲染失败。
- AI 接口失败或返回格式不兼容。

## 2. Beta 1 技术形态

Beta 1 采用“本地 Web 前端 + 本地控制服务”，不让浏览器直接持有 SSH 密码或执行系统命令。

```text
Browser UI
  React + TypeScript
        │ HTTP / SSE
        ▼
Local Controller
  Python + FastAPI
        │
        ├── 本机配置与凭据
        ├── 插件扫描与可信校验
        ├── SSH / SCP 执行
        ├── 运行状态与历史报告
        └── AI 兼容接口
```

约束：

- 默认只监听 `127.0.0.1`，Beta 1 不提供公网部署模式。
- 前端不保存服务器密码、私钥内容或 AI API Key。
- 敏感配置进入系统钥匙串；非敏感配置进入本机应用数据目录。
- HTTP API 从 `/api/v1` 开始版本化。
- 长任务通过 SSE 推送阶段状态和经过脱敏的实时输出。
- OpenAPI、插件 Schema 和报告 Schema 是 WebApp 与未来 macOS 客户端的共享契约。
- 当前原生 HTML 原型保留为交互基线，页面迁移到 React 后不得改变已经确认的主流程。

建议目录：

```text
poethan-sentinel-webapp/
├── frontend/           React + TypeScript + Vite
├── controller/         FastAPI 本地控制服务
├── contracts/          OpenAPI 与 JSON Schema
├── fixtures/           脱敏的演示数据与失败样例
├── tests/
└── prototype/          当前 HTML/CSS/JS 原型
```

## 3. 插件可信度校验

这是 Beta 1 的发布阻断项。

### 3.1 要解决的问题

可信校验需要同时回答：

1. 插件是谁发布的？
2. 插件内容是否在发布后被修改？
3. 同一个插件版本是否被替换成了另一份内容？
4. 上传到服务器后的文件是否仍与本机验证通过的内容一致？

只保存一个 SHA-256 不能证明发布者身份，因此 Beta 1 使用“发布者公钥 + 文件摘要清单 + 数字签名”。

### 3.2 插件包格式

```text
doris-diagnostic/
├── plugin.yaml
├── plugin.lock.json
├── plugin.sig
├── run.sh
├── src/
└── report/
```

`plugin.lock.json` 使用规范化 JSON，至少包含：

```json
{
  "lockVersion": 1,
  "plugin": {
    "id": "doris-diagnostic",
    "version": "0.3.0"
  },
  "publisher": {
    "id": "poethan-official",
    "keyId": "poethan-release-2026-01"
  },
  "files": [
    {"path": "plugin.yaml", "sha256": "..."},
    {"path": "run.sh", "sha256": "..."},
    {"path": "src/main.py", "sha256": "..."}
  ]
}
```

规则：

- `files` 包含所有可执行、配置、知识库、Schema 和模板文件。
- 不包含 `plugin.lock.json` 自身和 `plugin.sig`。
- 文件路径使用 `/`、按字典序排列，不允许绝对路径、`..` 或符号链接。
- SHA-256 对文件原始字节计算，不做换行转换。
- `plugin.sig` 是对规范化 `plugin.lock.json` 的 Ed25519 签名。
- `plugin.yaml` 中的 ID、version、publisher 必须与 lock 文件一致。

### 3.3 受信发布者

App 维护受信发布者列表：

```json
{
  "publishers": [
    {
      "id": "poethan-official",
      "keyId": "poethan-release-2026-01",
      "publicKey": "base64...",
      "pluginScopes": ["doris-*", "host-*", "network-*"]
    }
  ]
}
```

Beta 1 默认策略：

- 官方发布包：签名有效才允许安装和执行。
- 已安装版本：记录 `id + version + lockDigest`，同一版本摘要变化时阻止覆盖。
- 未签名插件：默认阻止，仅在“开发者模式”中允许，并显示持续的“不受信”标记。
- 未知发布者：允许用户导入公钥后信任，但必须展示发布者指纹和影响范围。
- 私钥不进入仓库、不进入 App，只存在于离线发布环境或受保护的 CI Secret。

### 3.4 三次验证

#### 导入前

- 校验目录结构、大小、符号链接和路径穿越。
- 校验 `plugin.yaml`、报告 Schema 和模板资源。
- 重算 lock 文件中的全部 SHA-256。
- 使用受信公钥验证 Ed25519 签名。
- 检查插件 ID、版本和发布者作用域。
- 页面展示发布者、Key ID、签名状态和内容摘要。

#### 上传服务器前

- 再次重算本机插件摘要，防止导入后文件被修改。
- 生成确定性的传输归档并计算归档 SHA-256。
- 将验证结果写入本次运行审计记录。

#### 上传服务器后

- 服务器对临时归档重新计算 SHA-256，必须与客户端一致。
- 解包后按 `plugin.lock.json` 再次核对所有文件摘要。
- 安装到 `<pluginHome>/<id>/<version>/<lockDigest>/`，不覆盖已有内容。
- 安装目录写入只读验证记录；每次执行前至少核对 lock digest 和入口文件摘要。

### 3.5 信任边界

签名只能证明“来源可信且内容未被篡改”，不能证明脚本行为安全。

Beta 1 还需要：

- `plugin.yaml` 声明所需能力，例如网络访问、sudo、perf、读取日志和数据库只读账号。
- 安装前展示能力摘要。
- 官方插件坚持只读诊断；需要修改系统状态的插件不进入 Beta 1 官方仓库。
- 命令、原始输出和 AI 输入统一执行敏感信息脱敏。
- 远程临时配置权限为 `0600`，运行结束后清理。

## 4. WebApp 工作项

### M1：项目工程化与共享契约

- [ ] 将静态原型迁入 `prototype/`。
- [ ] 初始化 React、TypeScript、Vite 和基础测试环境。
- [ ] 初始化 FastAPI Controller。

验收：前端使用演示 API 可以完整走通当前原型中的所有页面。

### M2：服务器与凭据

- [ ] 服务器列表、新建、编辑、删除。
- [ ] SSH 别名、密钥和密码三种登录方式。
- [ ] 连接测试返回阶段、耗时和原始错误摘要。

验收：重启应用后配置保留，凭据不会出现在数据库、日志和浏览器存储中。

### M3：插件库与可信校验

- [ ] 插件目录配置、扫描和文件变更监听。
- [ ] 有效插件和失败目录同时展示。
- [ ] 实现插件 Schema 校验和清晰错误定位。
- [ ] 实现 lock 文件生成工具。
- [ ] 实现 Ed25519 签名 CLI。
- [ ] 实现受信发布者管理和签名验证。
- [ ] 实现开发者模式与未签名插件警告。
- [ ] 为三个官方插件生成首批签名包。
- [ ] 生成插件 SBOM 或最小文件清单。

验收：修改已签名插件任意一个字节后，导入和执行都会被阻止。

### M4：诊断执行工作流

- [ ] 单选插件并保存“服务器 + 插件”的上次配置。
- [ ] 根据 `plugin.yaml` 动态生成表单。
- [ ] 远端按 `id/version/lockDigest` 缓存插件。
- [ ] 上传后远端摘要复核。
- [ ] 运行配置放入 `/tmp`，权限 `0600`，结束后清理。
- [ ] SSE 推送 SSH、同步、执行、下载、报告阶段。
- [ ] 支持停止、超时、失败重试。
- [ ] 原始输出不阻塞进程，并支持服务器临时结果包下载。
- [ ] 保留每次运行的审计信息和插件摘要。

验收：Doris、主机性能、网络三个插件均可在真实 Linux 服务器完成运行和报告生成。

### M5：报告与 AI

- [ ] 诊断结论、原始输出、AI 分析三个固定标签。
- [ ] JSON Schema 校验失败时保留原始结果。
- [ ] HTML 模板在受限上下文中渲染，禁止任意外部脚本。
- [ ] AI 连接测试展示 HTTP 状态和原始响应。
- [ ] 支持 Chat Completions 和 Responses 响应格式。
- [ ] AI 分析异步运行，失败不影响本地报告。
- [ ] 发送 AI 前展示数据范围并执行脱敏。
- [ ] 历史报告搜索、复制、导出和再次检查。

验收：关闭 AI 也能完成诊断；AI 失败时原始输出和确定性结论完整可用。

### M6：公开发布准备

- [ ] 选择并添加开源许可证。
- [ ] 编写 5 分钟快速开始。
- [ ] 编写插件开发、签名和发布文档。
- [ ] 编写安全模型、隐私说明和漏洞反馈方式。
- [ ] 提供 macOS 一键启动/停止脚本。
- [ ] 发布包附带 SHA-256 checksum。
- [ ] 准备脱敏截图、GIF 和演示数据。
- [ ] 增加 CHANGELOG 和版本升级说明。
- [ ] 在干净 macOS 用户环境完成一次安装测试。
- [ ] 在至少一台真实 Linux 服务器完成端到端回归。

验收：公众号读者只按照公开文档，可以在 10 分钟内进入演示模式，在 20 分钟内完成一台服务器的首次诊断。

## 5. Beta 1 不做的内容

- 多租户、团队协作和公网 SaaS。
- 浏览器直接连接 SSH。
- 一次任意勾选多个诊断插件。
- 自动修复、重启服务或修改数据库参数。
- 插件市场、自动付费和远程代码推送。
- 完整容器沙箱；Beta 1 先依靠受信签名、能力声明和只读官方插件控制风险。
- Web 与 macOS 客户端同时迭代。Beta 1 优先完成 WebApp，流程稳定后再迁移 SwiftUI。

## 6. 发布门槛

以下条件全部满足后才能标记 `0.1.0-beta.1`：

- [ ] 从新建服务器到导出报告的真实闭环通过。
- [ ] 三个官方插件全部签名且验证通过。
- [ ] 篡改、重复版本、未知发布者和路径穿越测试通过。
- [ ] 密码和 API Key 未进入浏览器存储、日志或报告。
- [ ] SSH host key 变更能够阻止连接并明确告警。
- [ ] AI 服务不可用时仍能正常生成本地报告。
- [ ] 演示模式不依赖真实服务器和真实密钥。
- [ ] 安装、卸载、升级和缓存清理流程有文档。
- [ ] 发布包、插件包和校验文件均有 checksum。
- [ ] 公众号文章中的命令在干净环境重新验证。

## 7. 实施顺序

优先级固定为：

1. M1 工程与契约。
2. M2 服务器连接。
3. M3 插件可信校验。
4. M4 真实执行闭环。
5. M5 报告与 AI。
6. M6 发布材料和回归。

安全项不放到最后补。M3 完成前可以使用开发者模式调试，但不能制作公开 Beta 安装包。
